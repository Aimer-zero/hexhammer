# 未知突破 — 假设-验证循环(把"创造力"变成"纪律")

```
观察(已知:端口/banner/行为/错误信息/上下文)
  ↓
hypothesis add ×3~5(覆盖至少三个方向)
  ├─ 类比:这行为像已知的什么?(Caddy/Nginx/自研?)
  ├─ 协议矩阵:这个端口/格式可能说什么协议?
  └─ 边界:极限输入/空输入/编码/大小写/路径变体→行为差异?
  ↓
排序:cost=low 的先验(一发探测就能确认/排除的优先)
  ↓
执行 verify → hypothesis resolve(带证据摘录)
  ↓
证据更新:
  - confirmed → 沿此方向展开(新假设/直接利用)
  - refuted → 排除,转向下一假设
  - inconclusive → 升级验证方式或标记待定
  ↓
迭代:直到破局(找到入口/绕过/漏洞)或穷尽(所有假设 resolved)
```

## 规则

1. **先记录再验证**:任何猜想进 hypothesis(add)后才动手——不然上下文
   膨胀后你自己都忘了猜过什么;
2. **最小成本优先**:cost=low 的假设先验(一发探测),cost=high 的(可能
   触发防护/破坏服务)留到穷尽低成本假设后;
3. **证据是唯一裁判**:resolve 的 evidence 必须是工具输出/命令结果的
   摘录,不是你的推理;
4. **穷尽也是结论**:全部 refuted → 报"当前手段面内不可达",诚实收尾
   (0006 先例);
5. **类比迁移**:已确认的假设,其手法可以尝试迁移到相似面(0007 的
   SpEL 从 0004 迁移)。
